## 4. 误报 / 漏报分析

**误报（FP）1 例：JO-PRD-01 打在列表页。**
列表页商品卡天然只有图、价、折扣。若把"缺少规格/材质"判为信息不完整，会把所有电商列表页打成 high。修正：该规则只在**商品详情页**生效；列表页只看"价格与折扣是否有参照说明"。

**漏报（FN）3 例：JO-PRD-03、JO-PRV-01、JO-PRV-04。**
三者都依赖页脚区域，而页脚在静态 DOM 中不存在。若直接判"页面未展示经营者信息 / 未提供隐私政策"，就是把抓取限制当成商家违规 —— 这正是 README §接入边界 里禁止的推断。修正：这三条规则增加前置条件"页脚/导航已完整加载"，否则输出"不可观察，需人工确认"。

**未触发但值得记录：JO-ADV-07（Art 8(B) 有害或来源不明商品）。**
首页没有医疗/杀菌类宣称，规则未命中 —— 属正常空跑，不算漏报。

**结论：**
- 30 条规则中，单页可稳定触发的约 8–10 条（广告类 + 价格披露类）；隐私类与主体信息类依赖完整渲染。
- 规则本身可用，但**接入时必须带"可观察性前置条件"**，否则 FN 会被写成"商家违规"，风险高于漏报本身。

## 5. 复现

```bash
mkdir -p jo_sources && cd jo_sources
curl -sSL -A 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/124.0 Safari/537.36' \
  -o shein_jo.html 'https://jo.shein.com/'
sha256sum shein_jo.html   # 期望 df1663059dda29e2bc12c6217e28b33856b1f44555403f7278f1a46e3faf8948
grep -o 'خصم يصل إلى 90%' shein_jo.html | wc -l
grep -c 'JOD' shein_jo.html
```
